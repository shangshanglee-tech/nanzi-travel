# 小楠子爱旅行极地产品内容结构设计

- 记录日期：2026-08-14
- 关联基线：小楠子爱旅行小程序设计基线 v0.2
- 状态：已确认，待实施

## 目标

将已授权 HX 的 11 条南极路线，从英文官网资料升级为面向用户的中文顾问式内容，并沉淀为路线、船只、舱位、团期与逐日行程的结构化资料。用户可从路线或船只进入小程序客服会话，顾问能直接看到用户已选择的路线、日期、执行船和舱位上下文。

## 内容口径

- 中文内容采用高端旅行顾问式改写：准确传达官方事实，同时帮助用户理解路线价值、体验差异和决策重点；不做逐句直译。
- 每条中文内容保留官方来源链接、抓取时间和复核状态。
- 不编造精确登陆点、每日活动、价格、库存、可售状态或合同承诺。
- 具体行程受天气、冰况、野生动物和船长决定影响的说明，固定展示在产品详情的行程说明中。

## 数据关系

```text
船只
  → 舱位类型
  → 路线（多对多）
  → 团期（一个团期对应一艘明确的执行船）
  → 咨询上下文
```

首批范围为 3 艘船：`MS Roald Amundsen`、`MS Fridtjof Nansen`、`MS Fram`；以及当前已导入的 11 条 HX 南极路线。

## 船只与舱位

每艘船建立独立详情档案，包含：中文定位、核心参数、公共空间、探险与服务特色、图片、关联路线，以及来源信息。

舱位属于船只，不属于路线。首版舱位资料包含中文舱型名称、面积、床型、窗景或阳台、适合人群、顾问式卖点和图片。舱位不记录实时库存、价格、团期可售状态或在线预订能力。

## 路线、团期与行程

每条路线包含中文概览、核心亮点、适合人群、费用与注意事项、可能执行船只、团期、逐日行程和官方来源。

路线可关联一艘或多艘船。路线详情展示“可能执行船只”的可跳转卡片，并注明具体执行船以所选团期为准。

每个团期保存出发日期、结束日期、标签、咨询状态和执行船。当前官方可查询团期全部补齐，并在用户选择日期后显示对应执行船卡片；该卡片可进入船只详情。

前端和后台行程统一按逐日记录保存。HX 官方原始区间行程（例如 `Day 3–4` 或 `Day 5–9`）拆为对应的每日记录，并保留 `source_range` 作为原始出处。相同区间内的每天复用同一份中文说明：跨越德雷克海峡时逐日显示同一段海上航行与准备内容；南极探索窗口则逐日显示“南极探索日”等相同说明，并明确这是天气和冰况驱动的弹性探险安排。

## 页面结构

### 首页

首页保留路线卡片，并增加 3 艘船的独立入口卡片。船只卡片不是筛选器，而是独立内容入口。

### 路线详情

1. 中文概览、亮点和适合人群；
2. 可能执行船只的可跳转卡片；
3. 团期选择器，展示日期、天数和执行船；
4. 选中团期后的执行船卡片；
5. 逐日行程；
6. 固定咨询入口。

### 船只详情

1. 船只定位、参数、公共空间和服务特色；
2. 舱位分类与卖点；
3. 这艘船关联的路线卡片；
4. 固定咨询入口。

## 咨询上下文

首版咨询升级为小程序内客服会话，由合伙人本人在微信客服工具中人工接待；公众号继续承担品牌内容与关注入口，但不作为本次带上下文咨询的承接通道。

点击“咨询”时，按当前页面选择组装并透传上下文：

```text
咨询来源：12天南极半岛精华
团期：2026-12-09
执行船只：MS Roald Amundsen
舱位：未选择
```

从船只或舱位页进入时，至少携带当前船只和当前舱位。用户未选择日期或舱位时，将明确传递“未选择”，不伪造偏好。客服会话中同时展示可返回对应小程序页面的内容卡片。

## 内容生产与维护

1. 从已授权 HX 官方路线、船只与舱位资料读取内容；
2. 转换为结构化草稿；
3. 生成顾问式中文文案；
4. 由运营方复核关键事实并发布；
5. 后续同步只更新团期和执行船关系，不覆盖已复核中文文案。

AI 后续只读取已发布、已确认的结构化内容，用于辅助顾问解释、检索和推荐。

## 本次不做

- 在线支付、订单、合同、收款；
- 实时舱位库存和价格；
- 对外开放的 AI 顾问或自动成交；
- 真实找搭子功能；
- 多顾问分配和 CRM 管理后台。
