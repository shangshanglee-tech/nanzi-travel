# 船只内容模板与电脑端内容后台设计

## 目标

以 MS Roald Amundsen（阿蒙森号）为首个完整样本，固化一套可复用于 HX 及其他公司的船只内容模板。后台用于电脑端编辑和发布；小程序只展示已发布的内容。

纯内容更新无需重新上传微信体验版。已安装的体验版在重新进入页面或刷新数据后读取已发布的线上内容。仅页面、交互或数据结构变更才需要上传新的体验版代码包。

## 内容原则

- 完整保留官方事实资料，不因当前页面的展示方式而丢弃字段。
- 英文原文与中文运营文案并存；英文用于核对，中文用于小程序展示与人工润色。
- 资料层与展示层分离：同一批舱位资料可按大类、官方代码或未来任意标签展示，无需重录数据。
- 每项内容保留官网来源与最后核对日期；每张图片保留来源、原始说明和使用备注。
- 不在船只静态资料中维护实时价格、余位或可售状态；这些属于团期/销售层。

## 数据结构

### 船只

- 中英文名称、所属公司、官方链接、资料核对日期。
- 载客量、建造年份、翻新年份、船型定位等基础事实。
- 首页短卖点、中文完整简介、英文原始简介。
- 封面图与船只通用图集。
- 草稿/已发布状态、排序及更新时间。

### 船上体验模块

每艘船可有任意数量、任意类型的内容模块，例如科学中心、餐厅、酒廊、观景空间、泳池/桑拿和探险服务。

每个模块包含：类型、中文标题与文案、英文原文、图片组、排序、是否展示和来源信息。没有对应资料的船不创建模块，前端不显示空区块。

### 舱位与具体舱型

舱位大类可为套房、阳台房、海景房、内舱等，并允许以后新增或调整。每个具体舱型均独立保留：

- 官方代码、英文名称与中文名称。
- 英文原文与中文运营文案。
- 面积、最大入住人数、床型、甲板、窗/阳台/景观、无障碍标识。
- 设施、卖点、可用于未来筛选的展示标签。
- 图片组、排序、来源信息。

具体舱型可关联多个展示标签；页面分组策略不改变原始舱位资料。

### 媒体与来源

图片作为独立媒体资源，关联到船只、船上体验模块或具体舱型。媒体存入自有存储，不在小程序直接热链官网资源。每条媒体记录保留来源 URL、原始说明、授权/使用备注和核对日期。

## 电脑端后台

后台入口为受保护的 Web 页面。船只编辑页采用以下分区：

1. 船只基础
2. 船上体验
3. 舱位
4. 图片与来源
5. 小程序预览与发布

编辑人员可保存草稿；预览只读取草稿；发布将该船的已确认内容写为线上版本。发布动作不改变路线、团期、价格或库存。

## 小程序船只详情页

展示顺序为：

1. 封面、核心卖点与基础事实
2. 船只简介
3. 船上体验图文模块
4. 舱位与套房（初版按大类组织，保留切换到官方代码展示的能力）
5. 关联路线（系统根据路线与团期关系自动生成）
6. 携带船只上下文的咨询入口

小程序没有编辑入口。内容更新后，小程序通过线上 API 读取新发布内容。
