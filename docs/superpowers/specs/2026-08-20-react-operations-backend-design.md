# React 运营后台设计

## 目标

以 React + Ant Design 替代现有 Django Admin，作为小楠子爱旅行唯一的日常运营后台。第一期只覆盖旅行产品、目的地、船只；不改变小程序现有的公开数据接口与用户端表现。

## 入口与身份

- `admin.nanzitravel.com` 提供新的 React 运营后台。
- Django 提供同域管理 API，并承载 React 的构建产物。
- 未登录用户只能访问登录页；所有管理 API、图片上传与写入操作都要求管理员会话。
- 第一期开通唯一超级管理员：`admin`。初始密码由部署配置提供，必须在对外开放前更换为强密码。
- 使用带 CSRF 保护的同域、HttpOnly 会话 Cookie；不使用浏览器可读的长期令牌。

## 运营信息架构

左侧导航只保留一个不可点击的“内容配置”分组：

1. 旅行产品
2. 目的地
3. 船只

不在新后台提供站点设置、用户、组、角色或系统管理入口。

## 功能范围

### 旅行产品

- 列表、关键词搜索、状态及目的地筛选。
- 创建、编辑、删除、发布与下架。
- 维护基础信息、目的地、关联船只、团期、每日行程、图片、亮点、费用包含/不含、适合人群与提醒。

### 目的地

- 列表、创建、编辑、启用状态与排序。
- 维持轻量的分类能力，为产品筛选与推荐提供基础数据。

### 船只

- 基础信息、卡片图、卡片底色、结构化事实。
- 页面内容分组标题与多图内容卡片编排。
- 舱位、舱位展示分组、甲板图。
- 图片上传、缩略图预览、删除确认与排序。

### 统一交互

- Ant Design 的布局、菜单、表格、表单、弹窗/抽屉、消息提示和删除确认。
- 列表页直达编辑页；不在首页显示“增加 / 修改”成对操作。
- 保存成功后提供明确提示；离开未保存编辑页时提示确认。

## 非目标

- AI 导入与内容校对。
- 订单、签约、找搭子运营管理。
- 多账号、角色和权限体系。
- 站点设置、用户与组管理。
- 对小程序公开 API 的字段或路径改造。

## 技术边界

- Django 保留模型、迁移、文件存储、业务校验、会话认证和管理 API。
- React 负责运营界面，不直接访问数据库。
- 新管理 API 位于独立的受认证路由空间，避免与现有公开 API 混用。
- 现有公开 API 保持兼容，避免影响已发布的小程序。

## 迁移与下线

1. 建立管理员登录、React 外壳、同域管理 API 基础设施。
2. 先实现目的地，再实现旅行产品，最后迁移船只复杂编辑能力。
3. 使用已有真实内容核对保存、图片、排序与小程序展示。
4. 三类内容均可由 React 后台完成日常维护后，删除 Django Admin 路由、模板和旧管理脚本。

## 验收标准

- 管理员可仅通过新后台完成三类内容的新增、编辑、删除、图片维护、排序和发布。
- 未登录用户不能读取或修改管理 API 数据。
- 任意新后台保存操作后，小程序公开内容按现有规则正确更新。
- Django Admin 不再作为可访问或可维护的运营入口。
